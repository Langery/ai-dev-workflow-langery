# Prompt 05：文档生成

> 让 Claude 为代码自动生成 README、API 文档、变更日志。

## 使用场景

新功能上线要写文档、老代码没文档想补、CHANGELOG 不想手写。

## Prompt

```
请为以下代码生成文档。

## 待文档化的代码
<贴代码，或指定文件路径>

## 文档类型
（选一个：README / API / CHANGELOG）

## 要求

### 如果是 README
1. 包含：项目简介 / 安装 / 启动 / 配置 / 使用 / 测试 / 部署
2. 安装步骤要能复制粘贴直接跑
3. 配置项用表格列出：变量名 / 必填 / 默认值 / 说明
4. 命令行用 ```bash 代码块
5. 不要写"为什么这么设计"，那是 CHANGELOG 的事

### 如果是 API 文档
1. 每个 endpoint 一段：
   - 路径 + 方法
   - 请求参数（表格：参数 / 类型 / 必填 / 说明）
   - 响应示例（成功 + 错误）
   - 错误码表
2. 不要写实现细节，只写接口契约
3. 用表格不用段落，方便扫读
4. 字段名用 `反引号`

### 如果是 CHANGELOG
1. 按 Keep a Changelog 格式
2. 分类：Added / Changed / Deprecated / Removed / Fixed / Security
3. 每条写「改了什么」+「为什么改」+「影响范围」
4. 关联 commit hash（短 hash 即可）
5. 版本号按 SemVer

## 输出

直接给 markdown 文档，不要解释生成过程。
```

## 实际案例

参考一个真实交付的变更日志，按既有章节格式追加 3 段（下面用中性占位符，实际写你项目里的真实对象名）：

- 业务实体段：<主表> 表 + 4 endpoint + owner 隔离 + sort 白名单 + uuid 生成
- 用户偏好段：<偏好表> 一行 per user + upsert + size/item 上限 + "不主动同步"语义
- 内容数据段：<内容表> 表 + 100 条 seed（10 真 + 90 模板）+ 3 endpoint + 循环 import 解法

每段含：目的 / 改动范围表 / endpoint 设计表 / 关键设计点 / 验证日志 / 不在本轮范围 / 风险；末尾整体回顾列出 3 个 commit hash 供追溯。

## 反例

❌ "帮我写个 README" —— 不知道读者是谁，会写成自说自话
❌ 不指定文档类型 —— Claude 会混着写，既像 README 又像 API 文档
❌ 不给代码 —— Claude 凭空编，文档和实现对不上
